# Lesson 5 — IaC (Terraform)

Terraform-структура для розгортання базової інфраструктури в **AWS**:

1. **Синхронізація стейт-файлів** — S3-бакет для зберігання `terraform.tfstate`
   та DynamoDB-таблиця для блокування стейту.
2. **Мережева інфраструктура (VPC)** — VPC із 3 публічними та 3 приватними
   підмережами, Internet Gateway, NAT Gateway та маршрутизацією.
3. **ECR** — реєстр для зберігання Docker-образів з автоматичним скануванням.

Проєкт побудовано на модулях: кожен блок інфраструктури винесено в окремий модуль,
а кореневий `main.tf` лише підключає їх.

## Структура проєкту

```text
lesson-5/
├── main.tf                 # Провайдер та підключення усіх модулів
├── backend.tf              # Налаштування бекенду для стейту (S3 + DynamoDB)
├── outputs.tf              # Загальне виведення ресурсів з усіх модулів
│
├── modules/                # Каталог з усіма модулями
│   │
│   ├── s3-backend/         # Модуль для S3 та DynamoDB
│   │   ├── s3.tf           # S3-бакет (версіювання, шифрування, блокування публічного доступу)
│   │   ├── dynamodb.tf     # DynamoDB-таблиця для блокування стейту
│   │   ├── variables.tf    # Змінні для S3 та DynamoDB
│   │   └── outputs.tf      # Виведення інформації про S3 та DynamoDB
│   │
│   ├── vpc/                # Модуль для VPC
│   │   ├── vpc.tf          # VPC, підмережі, Internet Gateway, NAT Gateway
│   │   ├── routes.tf       # Таблиці маршрутизації та їх асоціації
│   │   ├── variables.tf    # Змінні для VPC
│   │   └── outputs.tf      # Виведення інформації про VPC
│   │
│   └── ecr/                # Модуль для ECR
│       ├── ecr.tf          # ECR-репозиторій, сканування, політики
│       ├── variables.tf    # Змінні для ECR
│       └── outputs.tf      # Виведення URL репозиторію ECR
│
├── .gitignore              # Ігнорування .terraform/, стейтів, tfvars тощо
└── README.md               # Документація проєкту
```

## Опис модулів

### `s3-backend` — віддалений стейт
Створює інфраструктуру для зберігання стейту Terraform:
- **S3-бакет** для файлів `terraform.tfstate`;
- **версіювання** бакета — зберігає історію змін стейту;
- **шифрування** (SSE, AES256) та повне **блокування публічного доступу**;
- **DynamoDB-таблицю** з ключем `LockID` для блокування стейту, щоб унеможливити
  одночасну зміну інфраструктури кількома людьми.

Виводить: ім'я та URL S3-бакета, ім'я DynamoDB-таблиці.

### `vpc` — мережева інфраструктура
Створює мережу з CIDR `10.0.0.0/16`:
- **3 публічні підмережі** (`10.0.1.0/24`, `10.0.2.0/24`, `10.0.3.0/24`) з
  автоматичним призначенням публічних IP;
- **3 приватні підмережі** (`10.0.4.0/24`, `10.0.5.0/24`, `10.0.6.0/24`);
- **Internet Gateway** — вихід у інтернет для публічних підмереж;
- **NAT Gateway** (+ Elastic IP) — вихідний трафік із приватних підмереж;
- **Route Tables** — окрема таблиця маршрутів для публічних (через IGW) та
  приватних (через NAT) підмереж з відповідними асоціаціями.

Виводить: ID VPC, списки ID публічних і приватних підмереж, ID IGW та NAT.

### `ecr` — реєстр Docker-образів
Створює ECR-репозиторій:
- **автоматичне сканування образів** на вразливості під час `push` (`scan_on_push`);
- **шифрування** образів (AES256);
- **політику доступу** (`repository policy`) — push/pull у межах поточного AWS-акаунта;
- **політику життєвого циклу** — зберігає лише останні 10 образів.

Виводить: URL, ARN та ім'я репозиторію.

## Передумови

- Встановлений [Terraform](https://developer.hashicorp.com/terraform/install) `>= 1.5.0`.
- Налаштовані облікові дані AWS (напр. `aws configure` або змінні середовища
  `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`).
- **Унікальне ім'я S3-бакета.** Ім'я бакета глобально унікальне в межах усього AWS,
  тому перед запуском змініть значення `bucket_name` у `main.tf` **та** `bucket`
  у `backend.tf` на власне (в обох місцях воно має збігатися).

## Порядок запуску (bootstrap)

S3-бакет і DynamoDB-таблиця, вказані в `backend.tf`, самі створюються модулем
`s3-backend`. На найпершому запуску їх ще не існує (замкнене коло: `backend.tf`
посилається на бакет, якого ще немає), тому бекенд налаштовується поетапно:

**Крок 1. Створити лише бакет і таблицю з локальним стейтом.**
Тимчасово закоментуйте блок `backend "s3"` у `backend.tf`, після чого виконайте:

```bash
terraform init                              # локальний стейт
terraform apply -target=module.s3_backend   # створити лише S3-бакет і DynamoDB
```

**Крок 2. Перенести стейт у S3.**
Розкоментуйте блок `backend "s3"` у `backend.tf` і виконайте:

```bash
terraform init -migrate-state
```

Terraform запропонує скопіювати локальний стейт у S3 — підтвердьте (`yes`).

**Крок 3. Розгорнути решту інфраструктури.**

```bash
terraform apply     # створює VPC та ECR; стейт уже в S3 з блокуванням через DynamoDB
```

> Примітка: сучасний Terraform уміє блокувати стейт вбудованим механізмом
> `use_lockfile` (lock-файл у S3) без DynamoDB. Тут навмисно використано
> **DynamoDB** — так вимагає умова завдання.

## Команди

```bash
terraform init      # ініціалізація: провайдери, модулі, бекенд
terraform plan      # попередній перегляд змін
terraform apply     # створення / оновлення ресурсів у AWS
terraform destroy   # видалення усіх створених ресурсів
```

Переглянути значення виводів (outputs) після `apply`:

```bash
terraform output
```

## ⚠️ Видалення інфраструктури

Невикористані ресурси в AWS можуть призводити до витрат — після перевірки
**обов'язково видаляйте створені ресурси** командою `terraform destroy`.

Пам'ятайте про **порядок**: `terraform destroy` видаляє в тому числі S3-бакет і
DynamoDB-таблицю, у яких зберігається стейт. Щоб коректно все прибрати:

1. Перенесіть стейт назад у локальний файл: закоментуйте блок `backend "s3"` у
   `backend.tf` і виконайте `terraform init -migrate-state`.
2. Виконайте `terraform destroy` — тепер стейт зберігається локально й не
   заважає видаленню бакета (бакет має `force_destroy = true`).
